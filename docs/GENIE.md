# Optional Genie analysis

Create a Genie Space in your own workspace after the pipeline succeeds. Choose an appropriate SQL warehouse and add these UC tables, substituting your catalog and schema:

- `<catalog>.<schema>.credit_features_silver`: synthetic features and rule-derived risk tiers.
- `<catalog>.<schema>.decision_log`: the decisions generated by notebook 05.

Configure the Space in the workspace UI and grant its intended users the required warehouse/table access. This setup does not grant broad access or create a separate chatbot in the App.

Suggested instructions:

> All data and labels are synthetic. A model score is not a validated probability of default. The tables are batch snapshots. App decisions written to Lakebase are not automatically reflected in this Delta decision log. Count decision rows with COUNT(*); a customer can have several decisions. Use features_snapshot to reconstruct the historical inputs rather than joining to current features. State the table and freshness limitations in answers.

Try these questions and inspect the generated SQL:

- How many customers are in each risk_tier?
- How many batch decisions were APPROVE and DECLINE, and what is the approval rate?

Compare the results against direct SQL:

```sql
SELECT risk_tier, COUNT(*) AS customers
FROM <catalog>.<schema>.credit_features_silver
GROUP BY risk_tier;

SELECT decision, COUNT(*) AS decisions
FROM <catalog>.<schema>.decision_log
GROUP BY decision;
```

Set the optional `GENIE_SPACE_URL` environment variable in your App configuration to your own Space URL, then redeploy. The App shows a link when the variable is set. Users authenticate and access the Space under its own permissions. Leave the variable unset to omit the link.

The operational Risk Officer screen reads Lakebase; Genie reads the selected Delta snapshots. Continuous analysis of new App decisions needs a separately designed refresh/synchronization process with an explicit freshness objective.
